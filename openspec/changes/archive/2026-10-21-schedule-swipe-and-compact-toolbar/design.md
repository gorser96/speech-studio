## Context

Мотивация — [proposal.md](proposal.md). Фактически приложение использует общий Compose UI в `shared` для Android/iOS. `App.kt` владеет `ModalNavigationDrawer` и `TopAppBar`; жесты drawer сейчас включены при `!appBusy`. `ScheduleScreen.kt` рисует режимы, прокрутку и две ветки нижней кнопки создания. Цепочка: UI → `ScheduleAction.ChangeViewMode` / `StartCreatingLesson` → `ScheduleViewModel.onAction` → состояние. Смена режима уже привязывает период к выбранной дате; создание подставляет начало выбранного дня.

## Goals / Non-Goals

**Goals:** согласовать горизонтальные жесты с существующей вертикальной прокруткой и общим верхним баром.

**Non-Goals:** изменения данных, бизнес-правил сохранения и платформенной навигации.

## Decisions

- Следовать разделам 4, 6, 20 и 25 `ARCHITECTURE.md`: изменения ограничены Presentation, состояние остаётся во ViewModel. Не добавлять repository/use case для UI-жеста.
- Отключить жесты `ModalNavigationDrawer` в общей оболочке. Это устраняет конфликт во всех разделах; открытие остаётся у существующей кнопки и сохраняет guard `appBusy`. Вариант включать жесты у закрытого drawer непригоден из-за требования открытия только кнопкой.
- В `ScheduleScreen` обрабатывать горизонтальное перетаскивание только в календарной ветке. Распознавать горизонтальное направление после touch slop, накапливать сдвиг, переключать один раз после завершения при пороге 56 dp; отменённый или короткий жест не переключает режим. Использовать актуальный режим и существующий `ChangeViewMode`, не pager с тремя одновременно построенными сетками. На крайних режимах переход отсутствует. Вертикальное движение не поглощать.
- Добавить кнопку с иконкой «+» и доступной подписью «Добавление занятия» в `TopAppBar.actions` только для корня расписания, с `enabled = !appBusy` и проверкой состояния в callback; запускать существующий `StartCreatingLesson()`. Удалить обе кнопки из `ScheduleScreen`, включая ветку загрузки. Иконка вместо текста выбрана по уточнению пользователя.
- Сохранить `SegmentedButton`, задав внешнюю базовую форму `RoundedCornerShape(8.dp)` через `itemShape`; это сохраняет соединённые сегменты и семантику выбора. Глобальную тему менять не требуется.

## Risks / Trade-offs

- Конфликт с прокруткой и нажатиями → осмотреть направление захвата жеста, отмену и единственный callback; проверить сохранение обработчиков тапов/двойного тапа в сетках.
- Случайный запуск создания во вложенном экране → видимость кнопки по `currentScreen == Schedule && editor == null`, блокировка через существующий общий busy.
- Ширина верхней строки → проверить компоновку подписи и заголовка по коду; фактический внешний вид и жесты требуют последующей ручной приёмки на устройстве.

## Проверки

- Сборка Android `:app:assembleDebug` проверяет совместимость общего Compose-кода и используемых API.
- Адресный осмотр кода по сценариям delta: четыре перехода, крайние режимы, сохранение даты, отсутствие жестового открытия drawer, видимость/блокировки кнопки, вертикальная прокрутка и тапы. Новые зеркальные unit-тесты для UI-делегирования не нужны.
- `openspec validate ... --strict` и `git diff --check`; обновить карты затронутых пакетов и зафиксировать незавершённую ручную приёмку в существующем статусе проверок.
- По действующему ограничению проекта эмулятор, установка и connected-тесты не выполняются. Осмотр кода и сборка не подтверждают фактическую работу жестов на устройстве.
